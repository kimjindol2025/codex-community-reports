## 191 MCP 관련 결과

- **OAuth 만료·refresh token**: 수집 범위에서 MCP access token 만료·refresh token 갱신의 새 직접 재현/해결은 없었다. Codex 로그인 token-exchange 스레드에는 방화벽 제어 재설정 후 복구됐다는 단일 사용자 댓글과, 최신 버전에서도 지속되면 오류·버전·발생시각을 Support에 제출하라는 새 공식 답변이 있었다. MCP 갱신 토큰 장애와 같은 원인이라고 단정하지 않는다. Windows 실행기 스레드의 새 공식 답변은 같은 setup-refresh 메시지 뒤에 여러 원인이 있어 기존 우회가 모두에게 맞지 않는다고 설명하고 버전·Windows 빌드·정확한 오류·비공개 로그를 요청했다. 과거 junction/소유권 우회는 이번 신규 해결로 넣지 않았다. ## 판정과 유용한 차이

- **공식 지원 답변**: 스킬은 제출 시점 스냅샷이며 번들 설치·새 대화로 시험하도록 안내했다. 초안 저장·큐 등록·승인 요청 전송도 readOnlyHint:false로 표시하라고 설명했다. 이는 공식 지원 계정의 안내이며 특정 191 구현의 준수나 동작을 이번 조사에서 시험한 것은 아니다.
- **자동 재개**: 공식 지원은 한도 초기화 후 run을 중단 지점에서 자동 재개하는 기능은 없다고 답했다. 다른 사용자의 cron 제안은 확인된 제품 기능/해결책이 아니다. [공식 답변](https://community.openai.com/t/neatlessly-continuing-a-subagent-run-that-exeeds-the-usage-limit/1392958/2)
- **해결 확인의 한계**: 로그인 문제에 방화벽 제어를 바꾼 뒤 복구됐다는 사용자 댓글이 있지만 정확한 변경·같은 환경 재현은 없다. CLI 대안은 지원 계정이 인정한 사용자 관측이다. MCP 갱신 토큰의 일반 해결로 확대하지 않는다.
- **과거 사건 구분**: 24일 게시된 bcache 안전 차단 보고의 77회는 작성자가22~23일에 기록한 회고 집계이며 이번24시간에 새로77회 발생했다는 뜻이 아니다. 오탐·모델 저하·근본 원인은 확정되지 않았다.
- **검증 판단(추론)**: 코드·계획·테스트가 서로 맞아도 원래 승인한 요구사항을 놓칠 수 있다는 범위 이탈 논의가 있다. 원본 요구사항·승인 변경·실제 산출물을 함께 대조하는 것이 191에도 유용하다. 모델 변경이나 문맥 압축이 원인이라는 설명은 커뮤니티 추정이다. [논의](https://community.openai.com/t/repeated-scope-drift-in-long-codex-tasks-agent-generated-assumptions-become-requirements/1409425/3)
