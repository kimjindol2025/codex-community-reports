## 우리 191 적용 판단 (분석)

- 191에서 현재 project_read는 content와 structuredContent가 함께 반환되고 파일 본문이 정상 노출됐다. 이번 조사 시점 조회에 대한 관측이며 모든 도구 정상 판정은 아니다.
- 향후 {}가 재현되면 서버 실제 HTTP 응답과 ChatGPT 노출 결과를 비교하고 structuredContent의 전체 데이터 일치를 검증할 가치가 있다.
- 도구 미노출·서버 도착 전 차단·서버 내부 bwrap 실패는 각기 다른 실패 지점이다. 로그로 구분하고 관련 지원 증거를 수집한다.
- 예약 조사 저장은 매 실행 실제 저장·원본 재읽기로 판정해야 한다. 예약 생성 성공이 미래 파일 저장 성공을 입증하지 않는다.

## 우선 확인할 항목

1. 빈 응답: content/structuredContent에 같은 전체 파일 내용과 SHA가 실리는지 실제 호출 비교.
2. 예약 저장: 읽기 성공만으로 쓰기 성공을 판정하지 않고 원본 재읽기 검증.
3. 도구 소실: 대화·KST 시각·tools/list 요약·서버 수신 여부를 기록해 지원 조사와 연결.
4. App Server cwd: 실제 child cwd와 목표 worktree 경로를 관측. Windows 제보를 Linux 원인으로 단정하지 않음.
